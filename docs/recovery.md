# Восстановление локального сервиса

Проверенный способ: остановленный backend/worker, SQLite backup API, новый каталог.
Не копируйте активный application.sqlite3 отдельно от WAL. Код использует отдельный
SQLite reader.backup под write-lock, копирует связанные файлы и проверяет их SHA-256.
Флаг `--stopped` — подтверждение владельца, не автоматическое обнаружение всех
чужих процессов. Очередь queued/running должна быть пуста; сначала завершите или
отмените задания. Не запускайте другие writers во время снимка.

## Снимок

1. Остановите launcher Ctrl+C. Убедитесь, что ваши backend и worker завершены.
2. В той же локальной конфигурации задайте новый приватный путь вне репозитория и
   вне backend root. Снимок может содержать закрытые данные/модели; не отправляйте его.

```powershell
$backup = Read-Host 'Новый абсолютный путь приватного снимка'
.venv\Scripts\python.exe scripts/recovery.py backup --stopped --destination $backup
```

Состав: `store/` (согласованная SQLite и файлы), `settings.json` без токена,
`manifest.json` со schema/database version и хешами, `dependencies/` с копиями
точных внешних split/reference/native model registry зависимостей профилей.
Не копируются произвольные соседние каталоги. Модель не обучается.
Пути оригинальных зависимостей в приватном manifest нужны для восстановления,
поэтому этот manifest также нельзя включать в публичный code-demo.

При сбое неполный новый каталог может остаться. Он не считается backup без целого
проверяемого manifest. Исходный сервис не очищается и не заменяется. Не переиспользуйте
неполный каталог для успешного снимка; выберите новый.

## Восстановление только в отдельный каталог

```powershell
$restore = Read-Host 'Новый абсолютный путь восстановленного backend'
.venv\Scripts\python.exe scripts/recovery.py restore --bundle $backup --destination $restore
$env:FORESTCHECK_BACKEND_ROOT = $restore
$env:FORESTCHECK_OPERATOR_TOKEN = (.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))")
$env:FORESTCHECK_OPERATOR_ID = 'local-operator'
$env:FORESTCHECK_ALLOWED_ORIGINS = 'http://127.0.0.1:4173'
# Выберите режим из settings.json снимка; synthetic для demo, real для настоящего сервиса.
$env:FORESTCHECK_DATA_MODE = 'synthetic'
.venv\Scripts\python.exe scripts/backend_local.py serve
```

В отдельных терминалах с тем же окружением:

```powershell
.venv\Scripts\python.exe scripts/backend_local.py worker
.venv\Scripts\python.exe scripts/static_local.py
```

Токен не восстановлен намеренно: задайте новый секрет; исходные авторы старых Review
остаются неизменными. Настройки режима/лимитов/CORS сравните с `recovery-settings.json`.
Отмена Review остаётся отдельным событием. Восстановление не переигрывает задания
и не применяет предложения заново. Проверьте список анализов, историю решений,
исходные/новые версии и скачивание экспортов прежде чем продолжить работу.

## Внешние зависимости и предел переноса

Сохранённые профили содержат прежние абсолютные привязки к доверенным реестрам,
split и reference snapshot. Restore не переписывает их и их хеши. История и
экспорты доступны в новом backend root. На той же машине при доступных прежних
приватных зависимостях совместимые анализы можно запускать штатно.

На другой машине автоматическая релокация моделей/реестров **не реализована**.
Копии лежат в `recovery-dependencies/`, соответствие — в `recovery-manifest.json`.
Не перезаписывайте оригиналы для «проверки». Владелец должен отдельно восстановить
приватный аналитический комплект в согласованные новые пути и зарегистрировать
новый профиль штатным `register-local`; старые анализы/профили не переписываются.
Пока этого нет, повторный анализ может быть недоступен. Это явное ограничение
MVP recovery, а не обещание полного автоматического disaster recovery.

Тесты: синтетическое принятое решение и отчёт после запуска восстановленного API,
committed WAL, проверка всех зарегистрированных артефактов, внешний dependency
snapshot, отказ при pending jobs, изменении байтов и существующем назначении.
Реальная проверка отдельно не создаёт ответы специалиста; её приватный receipt
подтверждает только реально выполненные чтения и совпадение артефактов.
