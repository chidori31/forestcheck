# Ответ эксперта и оставшиеся уточнения

Итерация 12.10.2026. Ответ передан владельцем; имя эксперта и дата самого ответа
не установлены. Здесь нет настоящих строк, закрытой схемы или результатов разметки.
Предметная готовность остаётся **PARTIAL**.

## Что разъяснено

| Содержание переданного ответа | Реализованное поведение | Граница утверждения |
|---|---|---|
| У выдела обязательны площадь, лесотаксационный номер и вид земель | Различаются отсутствие поля, пустота, parse_error, unknown; ноль сохраняется | Диапазон площади не установлен. Общий вид земель отделён от лесного подтипа |
| Для естественного насаждения нужен ярус | Иерархия выдел → виртуальный ярус → физические породные строки; проверка явно связанной категории | Нет доказанной полноты выгрузки/join — insufficient_data, не ошибка лесоустройства |
| У яруса «по идее должны быть Породы» | Отдельный сигнал при доказанном отсутствии; statistical_suspicion | Предположительная формулировка не нормативное противоречие |
| Повтор выдела исключается после совпадения ярусов и пород | Полное сравнение дерева независимо от порядка, с сохранением кратности; хеш подтверждается содержательным равенством | Нужны совместимые пространство ID, объект и период/версия. План неактивен; raw не удаляется |
| Одна высота древесная, целые метры; другая кустарниковая, 0,1 м | HeightMapping с привязкой к файлу, листу, позиции и основанию; обе единицы — м | Позиции не известны. Дробность не классификатор, 1,0 м допустимо для кустарника |
| Предложены открытые таблицы нормальных полных чистых насаждений | Две кандидатуры, отдельный реестр кандидатов и черновик сообщения | Таблицы, регион и пересчёт смешанных насаждений не утверждены |
| Возможны несколько размеченных примеров ошибок | Импорт sidecar-меток с before/source/version и проверкой пересечения split | Файлы не получены. Экспертные показатели NOT_RUN |
| Можно готовить презентацию в собственном шаблоне | Учтено в материалах демонстрации | Окончательные критерии промежуточной защиты не предоставлены |

## Наши инженерные решения

- Сравнение связок сохраняет также различия подроста и других дочерних сведений.
  Это защита сохранности, а не отдельная дословная норма эксперта.
- Физические строки неизменны. Виртуальный ярус содержит только согласованные
  атрибуты; конфликт не разрешается выбором первой строки. Его UUID не является
  source-record ID для исключения.
- Обе высоты не требуются одновременно. Повторное представление не создаёт две ошибки;
  два разных значения, неизвестный тип породы и отсутствие применимой высоты требуют проверки.
  Фраза «Если повторяется, или пустая — можете игнорировать» не означает разрешения
  пропускать любую высоту в любом контексте. Нет усреднения, переноса или масштаба ×10.
- Запас суммируется только для полной популяции детей, одинаковых определений,
  единиц, вида запаса, времени и древесной/кустарниковой группы с явным допуском.
  Родитель не входит в сумму детей; его запас не размножается по породам.
- `expert-preprocessing-1.0.0` описывает новые sidecars. Старые модели работают
  только со своими прежними контрактами; новое обучение не выполнялось.
- Старое предложение исключения равных raw-строк больше не является допустимым
  планом дедупликации. Исторические отчёты сохранены, никакой план не применён.

## Оставшиеся уточнения

| Вопрос | Причина / заблокированное решение | Безопасное поведение | Компоненты и повторные проверки |
|---|---|---|---|
| Какие буквы/позиции относятся к двум высотам; как трактовать обе разные/пустые? | Нельзя назначить поле и обязательность по одной подписи | Обе unresolved; raw/координаты сохранены | HeightMapping, признаки; перестановка, 1,0 м, conflict/missing, совместимость моделей |
| Для каждого запаса: единица, вид, уровень, время, округление? | Нельзя включить конкретные суммы/произведения | unavailable_reference/insufficient_data | Mapping, StockSumCheck/StockBalanceCheck, patch; units, кратность, округление |
| Какой кандидат роста подходит к территории, происхождению, составу/полноте? Интерполяция допустима? | Источник ещё не эталон конкретного объекта | Все found; нет регистрации, экстраполяции и пересчёта | Registry/applicability; диапазон, чистота/полнота, конфликт |
| Как подтвердить период/версию наблюдения и полноту выгрузки? | Равенство характеристик не доказывает копию события; неполный лист не доказывает отсутствие яруса | Неактивный план, ambiguous_duplicate, неполная проверка | Identity/coverage, сравнение связок; годы, join, межsplit-копии |
| В каком формате/назначении придут примеры; есть ли проверенные отрицательные случаи? | Привязка к версии/объекту и допустимость precision/recall | Строгий sidecar; ответы не генерируются, unlabelled не отрицательные | expert_labels/exposure/scorer; source/before/hash, пересечения, частичная разметка |
| Есть ли уточнённые критерии промежуточного выступления? | Финальная редактура защиты | Собственный шаблон; неподтверждённые лимиты не официальные | Материалы и сценарий; сверка с регламентом |

Не нужно повторно спрашивать о полном сравнении связок и смысловых назначениях
высоты: ответы уже получены. Другие категории покрытых лесов и межкнижные
соответствия не выводятся из одного подтверждённого случая.

Указанная экспертом [инструкция](https://docs.cntd.ru/document/351878696) не была
доступна как проверенный полный текст. Нормы из неё не извлекались и ретроспективно
не применялись. Подробнее: [кандидаты роста](growth_reference_candidates.md).

## Локальный запуск

После подготовки явных приватных binding/cohort-файлов:

```powershell
.venv\Scripts\python.exe scripts\review_expert_local.py --config configs\local.expert-review.json
```

Проверяются хеши снимка, mapping, frozen split и список допущенных UUID до
предметного анализа. JSON/JSONL с иерархией, координатами, результатами правил
и неактивным планом сохраняются только в приватном хранилище; stdout — статус.
Отсутствующая конфигурация завершает запуск ошибкой, без demo.
Это локальная проверка XLSX-sidecars. API/UI по-прежнему принимает CSV;
новые проверки не выдаются за уже подключённую функцию интерфейса.
