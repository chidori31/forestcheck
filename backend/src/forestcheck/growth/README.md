# growth

`GrowthTableRegistry` выполняет поиск по явно переданным таблицам в памяти.
Допущенных реальных региональных таблиц нет; в поставку они не включены.
Пустой реестр всегда возвращает `unavailable_reference` / `no_registered_reference`,
включая неполный запрос; отсутствующие параметры сохраняются в `missing_fields`.

`GrowthTable`, `GrowthTableMetadata`, `GrowthQuery`, `GrowthLookupResult` требуют
`schema_version="1.0"`; неизвестные версии и поля отвергаются. Все снимки и их
вложенные значения неизменяемы. Таблица содержит версию, источник с названием
и разделом/страницей, регион, породу, происхождение, тип насаждения, бонитет
и/или условия, смысл показателя, единицы показателя и возраста, подтверждённый
возрастной диапазон, политику интерполяции и явную маркировку `synthetic`.
`None` в бонитете или условиях метаданных означает, что источник явно не использует
эту размерность; хотя бы одна из них обязательна. Точки должны покрывать заявленный
диапазон полностью, иметь строго возрастающие уникальные возрасты и конечные числа.

Вызов: `GrowthTableRegistry(tables).lookup(query)`. Каждая размерность применимости
должна совпасть буквально, включая единицы и обе размерности бонитет/условия.
Поиска «ближайшего» региона, приведения кодов, единиц или масштабирования по полноте
и составу нет. При наличии таблиц неполные запросы получают `insufficient_data`; несовпадения —
`unavailable_reference` с причинами в `mismatches`. Несколько применимых таблиц
также дают отказ `ambiguous_reference`; порядок регистрации не выбирает победителя.

По умолчанию доступны только точные возрастные точки. Линейная интерполяция
внутри диапазона требует одновременно `interpolation.method="linear"`, ссылки
на разрешающее её основание в `authorization` и `query.allow_interpolation=True`.
Экстраполяция не реализована. Успешный результат содержит значение, единицу,
метод, полный снимок метаданных и точки, подтверждающие значение.

Синтетические таблицы исключены из обычного поиска. Для механических тестов
их можно разрешить отдельным строгим boolean-флагом `allow_synthetic=True`.
В `tests/test_growth.py` все названия и числа придуманы самостоятельно; они
не являются лесотаксационными нормами. Маркировка остаётся в результате.

Реестр не читает файлы, не подтверждает права/достоверность источников, не
анализирует `Record`, не создаёт Finding/Suggestion и не меняет исходные записи.
Загрузка разрешённых таблиц, независимая проверка источников и их подключение
к реальному анализу остаются не реализованными.
