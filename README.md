# ForestCheck («ЛесКонтроль») — передача Windows code-demo

**Состояние: PARTIAL, локальный MVP.** Отсутствуют допущенная реальная таблица роста,
полные предметные справочники, независимая экспертная разметка и подтверждённый
формат конкурсной сдачи. IsolationForest не подключён к основному API-анализу.
Прогнозы восстанавливают непроверенные наблюдения; они не доказывают ошибку.
Нельзя представлять эту сборку как полностью выполненную предметную задачу.
Подробности: [release_notes.md](release_notes.md), [восстановление](docs/recovery.md).

Инженерное дополнение 10.10.2026: [структурированный XLSX-импорт](docs/xlsx_import.md)
работает отдельной локальной командой; API/UI по-прежнему принимает CSV.
[Сценарий защиты и резерв](docs/interim_demo.md),
[полученный ответ и оставшиеся уточнения](docs/expert_clarifications.md),
[свежие проверки и границы](docs/engineering_status.md).

Экспертная итерация 12.10.2026: добавлены локальные проверки обязательных полей,
иерархии и полных связок, явная семантика двух высот и импорт будущих меток.
Команда и ограничения — в [пояснениях](docs/expert_clarifications.md).
[Кандидаты таблиц роста](docs/growth_reference_candidates.md) пока не допущены
к расчётам. Новая семантика не меняет старые split/модели и не подключена к CSV UI.

Проверяемая среда: Windows 11, PowerShell, Python 3.13.0, Node 24.18.0,
npm 11.16.0, uv 0.12.24. WSL/Linux/macOS и Docker-сборка не проверены.
Docker CLI доступен, но Docker Desktop engine на машине проверки не запущен.
Используется существующий FastAPI/SQLite worker и React/TypeScript/Vite,
без миграции стека, облачного LLM или обязательного GPU.

## Установка из чистого каталога

Распакуйте code-demo ZIP в новый локальный каталог и откройте PowerShell в нём.
Python 3.13 и Node 24 должны быть установлены заранее. Если uv отсутствует,
установите его в локальное bootstrap-окружение:

```powershell
py -3.13 -m venv .bootstrap
.bootstrap\Scripts\python.exe -m pip install uv==0.12.24
.bootstrap\Scripts\uv.exe sync --locked --extra analytics --extra ml
Push-Location frontend
npm ci --ignore-scripts
npx --no-install playwright install chromium
Pop-Location
.venv\Scripts\python.exe scripts/release.py build
```

Если uv уже установлен, используйте `uv sync --locked --extra analytics --extra ml`.
Не устанавливайте реальные данные или модели через npm/pip. Lock-файлы:
`uv.lock`, `frontend/package-lock.json`. Подготовка зависимостей, build backend и
браузера может требовать интернет (PyPI/npm/загрузка Chromium). Пакет не является
полным offline wheelhouse. После установки и сборки анализ и просмотр работают
локально без обязательного внешнего API. Сервер статических файлов отдаёт только
`frontend/dist`, а не исходники, AGENTS или документы разработки.

## Demo: отдельный пустой корень

Выберите **новый пустой каталог вне распакованного проекта**. Значение ниже —
самостоятельно созданная синтетика во временном хранилище ОС, не настоящий путь:

```powershell
$env:FORESTCHECK_BACKEND_ROOT = Join-Path $env:TEMP ('forestcheck-demo-' + [guid]::NewGuid())
$env:FORESTCHECK_OPERATOR_TOKEN = (.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))")
$env:FORESTCHECK_OPERATOR_ID = 'local-operator'
.venv\Scripts\python.exe scripts/release.py demo
```

Откройте `http://127.0.0.1:4173`. Backend: `http://127.0.0.1:8000`.
Вставьте токен из своей переменной окружения в форму входа; не помещайте его в URL,
конфигурацию Git, скриншоты или журнал. В другом PowerShell переменная автоматически
не появляется. При необходимости скопируйте токен локально средствами терминала.
`Ctrl+C` в запустившем терминале завершает собственные процессы сервера/worker/UI.
Повторный demo требует нового пустого корня, чтобы не переименовать real-данные
в синтетику. Старую demo-БД можно открыть обычным backend после восстановления.

Сценарий demo:

1. Убедитесь в маркировке **«Синтетические данные»**.
2. Загрузите `frontend/public/demo/synthetic.csv` (360 придуманных строк).
3. Подтвердите mapping из `frontend/public/demo/mapping.json` и единицы.
4. Выберите синтетический арифметический профиль, запустите анализ.
5. Откройте пропуск общего запаса: исходное значение пустое, предложение 20 м³
   получено из 10 м³/га × 2 га. Это тест проводки, не лесная методика.
6. Раздельно подтвердите ошибку и примите значение либо отклоните предложение.
7. Создайте новую версию из принятых решений и экспортируйте отчёт/версию.
   Оригинал и raw не изменяются.

Demo не содержит настоящих весов и не подставляет фиктивный ответ вместо ML.
Отключённый/недоступный ML не отключает арифметические проверки.

## Тесты и синтетический benchmark

```powershell
.venv\Scripts\python.exe scripts/release.py tests
$bench = Join-Path $env:TEMP ('forestcheck-benchmark-' + [guid]::NewGuid())
.venv\Scripts\python.exe scripts/release.py benchmark --private-output $bench
```

`tests` запускает pytest, Ruff, frontend build/typecheck, ESLint, Vitest и Playwright.
Тесты используют только собственную синтетику; небольшие ML-fixtures могут обучать
тестовые модели, но реальные веса не обучаются и не продвигаются. Для браузерных
тестов свободны 8123 и 5173. Benchmark проверяет фиксированные маленькие synthetic
workflow/recovery fixtures, включая решения и экспорт, под лимитом 900 с/4096 MiB,
2 библиотечных потока. Время включает pytest/setup; это не benchmark большого
лесного набора. `resources.json` содержит sampled process-tree RSS/время.

## Real: только существующие разрешённые артефакты

В code-demo нет реальных данных, mapping, split, правил, весов или приватных отчётов.
Создайте локальный `configs/local.ingest.json` по `configs/ingest.example.json`.
`source_dir` должен указывать только на разрешённую задачу №6; `private_dir` —
на существующее приватное хранилище этапов импорта/правил/split/ML/рекомендаций.
Официальную семантику программа не выводит автоматически. Не копируйте настройки
путей в публичный комплект. Задайте отдельный persistent backend root вне проекта:

```powershell
# Задайте локально реальные значения этих переменных; пример не является путём данных.
$env:FORESTCHECK_BACKEND_ROOT = Read-Host 'Отдельная приватная папка backend'
$env:FORESTCHECK_OPERATOR_TOKEN = (.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))")
$env:FORESTCHECK_OPERATOR_ID = 'local-operator'
.venv\Scripts\python.exe scripts/release.py real --config configs/local.ingest.json
```

Команда проверяет существующие локальные артефакты, регистрирует проверенный профиль
и запускает backend/worker/static UI. Она не обучает модель, не скачивает конкурсное
облако и не заменяет отсутствующий набор demo. Без конфигурации —
`REAL_CONFIG_REQUIRED`; без данных/проверенных артефактов —
`REAL_DATA_OR_VERIFIED_ARTIFACTS_UNAVAILABLE`. Загрузка CSV и подтверждение mapping
выполняются через UI; текущий real-профиль ограничен своим зарегистрированным набором.
Новый произвольный CSV не получает автоматически совместимую модель.

Источники читаются, производные пишутся в отдельный backend root. Нативный запуск
не создаёт Docker mounts: read-only доступ к исходному каталогу обеспечивается
правами ОС владельца; программа не меняет его ACL или атрибуты. При контейнеризации
в будущем источники должны монтироваться read-only, производные — отдельно.
Контейнерного Dockerfile/Compose в этом проверенном комплекте нет.

## Восстановление, offline и безопасность

Сначала остановите backend и worker, завершите/отмените очередь; используйте
[docs/recovery.md](docs/recovery.md). Backup приватный: содержит данные и зависимости,
его нельзя включать в code-demo. Восстановление только в новый каталог.

Серверы слушают только loopback: 8000 API, 4173 статический UI. Секрет из окружения,
автор решений задаётся сервером. Это локальный однопользовательский режим, не
обещание промышленной изоляции. CORS разрешает только локальный UI. Логи не нужны
для передачи данных. `.gitignore/.dockerignore` не являются защитой доступа.

Работа после установки проверяется запретом внешних соединений при синтетическом
анализе/восстановлении и просмотре UI. Это проверка конкретного сценария, не
доказательство отсутствия любых возможных соединений ОС, браузера или зависимостей.
Не запускайте установку, npm audit или обновление браузера в offline-сценарии.

## Неисправности

- `BUILD_REQUIRED`: выполните build после npm ci.
- `DEMO_REQUIRES_EMPTY_STORAGE`: используйте новый пустой demo-каталог.
- `RELEASE_FAILED_CHECK_LOCAL_CONFIGURATION`: проверьте внешний backend root,
  токен минимум 32 ASCII-символа, установленные зависимости и свободные порты.
- `CHILD_PROCESS_STOPPED`: один сервер завершился; остановлены собственные дочерние
  процессы. Проверьте занятые 8000/4173 и конфигурацию, не ослабляйте авторизацию.
- 401: токен формы должен совпадать с окружением backend.
- 409: обновите версию Review, сверьте сохранённый черновик; не подтверждайте вслепую.
- `unavailable_reference`: подходящий эталон отсутствует; это не успешная проверка.
- `RECOVERY_FAILED_CHECK_STOPPED_STATE_PATHS_AND_MANIFEST`: не удаляйте проверки;
  проверьте остановку, очередь, новый путь и целостность backup.

## Комплект и права

`MANIFEST.sha256` фиксирует состав code-demo; ничего автоматически не публикуется.
`third_party/dependencies.json` и notices сохраняют доступные уведомления библиотек;
бинарные зависимости устанавливаются отдельно. Собственному коду лицензия от имени
владельца не назначена. Разрешение ИИ — сообщение владельца; декларация отдельно
за ним. Правила закрытой конкурсной передачи ещё не подтверждены: закрытый комплект
не сформирован и не отправлен. Рабочие инструкции остаются в рабочем репозитории;
UI их не обслуживает. Их включение в конкурсные исходники нужно согласовать по
правилам сдачи, а не удалять ради сокрытия происхождения.
