# Release notes — этап 11

**PARTIAL. Не сняты блокеры:** реальная таблица роста, полные предметные словари/
семантика, независимая экспертная разметка, официальный формат/правила передачи.
Закрытый конкурсный комплект не определён и не отправлен. Разрешение ИИ не является
разрешением публиковать исходные данные или их производные.

Добавлено только release/operations: команды native Windows build/demo/real/tests/
synthetic benchmark, loopback static server только для dist, остановленный SQLite
backup/restore, каталог версий и upstream notices, явный code-demo allowlist и
контрольные суммы. ML/правила/API-контракты/React-поведение не переписаны. Настоящие
модели не обучались, holdout этапа 10 не оценивался повторно.

Docker Desktop engine недоступен; Compose/container/WSL не проверены и не поставляются.
После установки зависимостей работа локальная. Установка может обращаться к PyPI,
npm и дистрибутиву Chromium; полного offline wheelhouse нет. Windows ACL, шифрование,
резервное хранение и доступ к исходникам read-only обеспечивает владелец.

Backup содержит закрытые сведения, хранится отдельно. Проверяется история/экспорт
в новом корне. Внешние зависимости сохранены, но автоматическое перемещение
абсолютных привязок профилей на другую машину не реализовано.

В code-demo нет реальных данных, производных схем/отчётов, весов, локальной
конфигурации, секретов, личных путей и переписки. AGENTS/рабочие документы сохранены
в рабочей области; в конкурсный комплект они не включены автоматически при
неподтверждённых правилах. Это не изменение истории и не заявление разработки без ИИ.
Декларацию ИИ готовит владелец. Собственная лицензия не назначена.

Бинарные зависимости и node_modules не распространяются в архиве. Каталог
third_party сохраняет найденные license/notice файлы и версии. Некоторые установленные
пакеты содержат только метаданные/встроенные уведомления, что отмечено явно;
перед распространением готовых сторонних бинарников потребуется отдельная сверка
их полного лицензионного комплекта. Не считать этот каталог юридической аттестацией.

Фактические результаты release-проверок записываются в release_checks.json и
в рабочий docs/STATE.md. Успех упаковки отдельно от успеха запуска/восстановления.

Проверки передачи: 559 pytest + 6 subtests, Ruff, frontend build/typecheck/ESLint,
13 компонентных и 3 E2E теста — PASS. Launcher и собранный static UI проверены
отдельно с запретом внешней сети; real без конфигурации даёт явную ошибку.
Восстановление synthetic WAL/решения/экспорта и реального same-host сервиса — PASS.
Исправлен пусковой дефект отсутствующего work/ в чистой распаковке через RED/GREEN.
Детали и пределы измерений — release_checks.json. Подробные real receipts приватны.
